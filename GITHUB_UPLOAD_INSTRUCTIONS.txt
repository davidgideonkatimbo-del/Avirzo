AVIRZO v2.17.13 — ASSET AND VOICE RELIABILITY

This release improves queued film exports and background-job reliability, including durable SRT delivery, partial archive cleanup, safer cancellation, configurable retries and paginated provider polling. It also includes the v2.17.10 authentication recovery and local sign-out fixes. Finance alert retries and Runway invoice reconciliation remain included; see RELEASE_NOTES_v2.17.13.md and the historical release notes. Apply `supabase-export-job-reliability.sql` before deploying v2.17.13. Apply `supabase-finance-reconciliation.sql` after `supabase-provider-budget.sql` and `supabase-cross-instance-guardrails.sql`; configure `AVIRZO_FINANCE_ALERT_WEBHOOK_URL` on both the web service and worker if the worker is enabled. It also keeps scene-by-scene original instrumental music, generated through the ElevenLabs Music API. It carries Roots Foundation and World Bible music notes into the prompt and preserves each generated score as a separate editable timeline track.

Before deploying:
1. Configure ELEVENLABS_API_KEY as a server-side secret in Render. Music API access requires a qualifying paid ElevenLabs plan. Never put the key in client-side variables.
2. Confirm Supabase storage bucket avirzo-media and project asset permissions are configured to archive music to saved projects.
3. Upload the full ZIP contents to the existing repository, including hidden files and .github/workflows. Uploading files does not remove obsolete files already in GitHub.
4. If the old server/test/optimizations.test.js exists in GitHub and imports non-existent continuity exports, delete that obsolete file in GitHub and commit the deletion. Keep server/src/services/continuity.js and server/test/release.test.js.
